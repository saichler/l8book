Virtual Network Interface Card
IVNic • VNic.go
Purpose
Abstracts all network communication behind a single interface. Whether a service runs in-process, on another node, in Docker, or in Kubernetes — the calling code uses the exact same API. Provides six messaging patterns: Unicast, Multicast, RoundRobin, Proximity, Leader, and Local.
Positive Impact
  • Location transparency — moving a service between nodes requires zero code changes
  • Multi-topology support — same binary runs in native, Docker, and K8s by changing one constant
  • Built-in load distribution — RoundRobin and Proximity without external load balancers
  • Leader election built-in — no external consensus systems (etcd, ZooKeeper)
  • Simplified ServiceAPI — CRUD in single-line calls
AI Acceleration
AI generates correct inter-service communication on the first attempt because IVNic offers exactly one way to talk to a service. No ambiguity about transport, serialization, or routing. One pattern, everywhere.
Relevant Rules
single-owner-database-table.md framework-interface-boundaries.md never-edit-vendor.md
Example (l8erp)
// Cross-service data access in a callback ordersRaw, err := common.GetEntities( "MfgProdOrd", 70, &mfg.MfgProductionOrder{...}, vnic)

Resource Container
IResources • Resources.go
Purpose
The dependency injection container for the entire system. Instead of passing individual dependencies (logger, security, registry, introspector, services, events) through every function, a single IResources instance provides access to all of them.
Positive Impact
  • Single point of configuration — all system resources configured once, accessed uniformly
  • Zero dependency wiring — new services receive everything through one parameter
  • Environment portability — same code works across environments
  • Composition over inheritance — components access only what they need
AI Acceleration
AI never figures out "how do I get the logger?" — the answer is always resources.Logger(). No bootstrapping code, no dependency graph to reason about. When AI generates a new service, it receives IResources and immediately has access to everything.
Relevant Rules
security-provider-interface.md events-service-required.md vendor-third-party-code.md
Example (probler)
func CreateResources(alias string) ifs.IResources { log := logger.NewLoggerImpl(&logger.FmtLogMethod{}) res := resources.NewResources(log) sec, _ := sec.LoadSecurityProvider(res) res.Set(sec) return res }

Service Handler
IServiceHandler • Services.go
Purpose
Defines the universal contract for any service. Every service implements the same five CRUD methods (Post, Put, Patch, Delete, Get) plus lifecycle methods. The framework routes any message to any service without knowing what the service does.
Positive Impact
  • Universal CRUD semantics — every entity managed through the same five operations
  • Hot-pluggable services — activate/deactivate at runtime without restarts
  • Framework-managed routing — dispatcher needs no service-specific logic
  • Automatic web bridging — any service auto-exposed as REST endpoints
AI Acceleration
Creating a new service is pure template application. AI generates a *Service.go file with ServiceName, ServiceArea, Activate function, and lookup function — every time, the same structure. A complete, functional service in under 30 seconds.
Relevant Rules
maintainability.md protobuf-model-names.md mock-endpoint-construction.md data-completeness-pipeline.md
Example (l8erp)
const ( ServiceName = "MfgWorkOrd" // Max 10 characters ServiceArea = byte(70) // Same for all MFG services ) func Activate(creds, dbname string, vnic ifs.IVNic) { common.ActivateService(common.ServiceConfig{ ServiceName: ServiceName, ServiceArea: ServiceArea, PrimaryKey: "WorkOrderId", }, &mfg.MfgWorkOrder{}, &mfg.MfgWorkOrderList{}, ...) }

Service Level Agreement
ServiceLevelAgreement • ServiceLevelAgreement.go
Purpose
The declarative configuration object for a service. All operational characteristics — storage, replication, transactions, web endpoints, keys, caching — are declared in a single SLA struct. The framework reads the declaration and configures everything automatically.
Positive Impact
  • Declarative service definition — entire behavior declared in one place
  • Separation of concerns — developer declares "what"; framework provides "how"
  • Zero-code feature activation — SetReplication(true) enables replication
  • Consistent metadata — aggregation functions declared once, computed automatically
AI Acceleration
AI generates service configurations by filling in a structured template. Every SLA field has a clear purpose and constrained valid values. AI never designs an activation sequence or writes cache initialization — it declares the SLA and calls Activate.
Relevant Rules
maintainability.md layer8d-table-pagination-metadata.md single-owner-database-table.md
Example (l8erp)
// 14+ module groups, 20 parallel workers func ActivateAllServices(creds, dbname string, nic ifs.IVNic) { var all []func() all = append(all, collectHCMActivations(creds, dbname, nic)...) all = append(all, collectFinActivations(creds, dbname, nic)...) all = append(all, collectMfgActivations(creds, dbname, nic)...) // ... parallel activation with worker pool }

Service Lifecycle Callback
IServiceCallback • ServiceLevelAgreement.go
Purpose
Provides Before and After hooks for every CRUD operation. Before hooks validate and can abort. After hooks perform side effects (cascade updates, roll-up calculations). Receives the entity, action type, and VNic — everything needed for business logic.
Positive Impact
  • Business logic isolation — all rules in one file, separate from infrastructure
  • Operation-aware hooks — Action parameter enables action-specific validation
  • Abort capability — false from Before hook stops cleanly with error propagation
  • Cascading operations — After hooks update related entities via VNic
AI Acceleration
AI generates callbacks using a fixed template: type assertion, validation calls via the common.NewValidation builder, primary key generation, and After hooks. AI can generate a complete callback from a protobuf struct definition alone.
Relevant Rules
maintainability.md never-import-l8secure.md framework-interface-boundaries.md report-infra-bugs.md
Example (l8erp)
func newMfgWorkOrderServiceCallback(vnic ifs.IVNic) ifs.IServiceCallback { return common.NewValidation(&mfg.MfgWorkOrder{}, vnic). StatusTransition(workOrderTransitions()). After(cascadeRollUpProductionOrderStatus). After(rollUpCosts). Compute(computeWorkOrderProgress). Require(func(v interface{}) string { return v.(*mfg.MfgWorkOrder).WorkOrderId }, "WorkOrderId").Build() }

Service Registry
IServices • Services.go
Purpose
The central registry managing service registration, activation, deactivation, and message routing. Knows which services are running, where they are hosted, who is the leader, and how to dispatch messages. The backbone of the service mesh.
Positive Impact
  • Automatic service discovery — no config files, no DNS, no service mesh sidecars
  • Leader election — distributed consensus as a framework feature
  • Transparent routing — adding a service requires zero routing changes
  • Parallel activation — l8erp activates 100+ services with 20 parallel workers
AI Acceleration
AI never writes service discovery code. When AI generates a new service, it calls Activate and the service is discoverable. The entire service mesh topology is invisible to application code.
Relevant Rules
single-owner-database-table.md events-service-required.md log-services-required.md

Security Provider
ISecurityProvider • Security.go
Purpose
Consolidates all Authentication, Authorization, and Accounting (AAA) behind a single interface. Handles login, TFA, connection validation, encryption/decryption, action authorization, and row-level data scoping. Loaded as a plugin for deployment flexibility.
Positive Impact
  • Single security contract — all security concerns flow through one interface
  • Plugin architecture — different security implementations without code changes
  • Row-level scoping — ScopeView filters query results automatically per user
  • Encrypted messaging — every message body encrypted by default
  • Connection-level security — network ACL before any data exchange
AI Acceleration
AI never writes auth, authz, or encryption code. Security is automatically enforced by the framework. When AI generates a security config, it follows a declarative JSON format (roles, rules, deny expressions) requiring no programming.
Relevant Rules
security-provider-interface.md security-config-structure.md security-provisioning-channels.md never-import-l8secure.md associate-ids-scope-view.md

Type Registry
IRegistry • Registry.go
Purpose
Provides dynamic type registration and instantiation. Any protobuf type can be registered by name and new instances created at runtime without compile-time type knowledge. Foundation for generic serialization, deserialization, and message routing.
Positive Impact
  • Dynamic type instantiation — NewOf(instance) creates typed objects from raw bytes
  • Enum unification — central enum string-to-int mapping for query engine
  • Type list discovery — UI introspection discovers models automatically
  • Pluggable serialization — per-type custom serializers without framework changes
AI Acceleration
AI registers types with a one-line pattern: common.RegisterType(resources, &Type{}, &TypeList{}, "PK"). No switch statements for type dispatch, no factory patterns, no lookup tables. When AI generates a module, type registration is one call per entity.
Relevant Rules
maintainability.md protobuf-model-names.md proto-list-convention.md protobuf-generation.md

Type Introspection
IIntrospector, IDecorators • Introspector.go
Purpose
Runtime type analysis that builds metadata trees for every registered type. IDecorators extend metadata with application semantics: primary keys, unique constraints, merge rules. Enables the framework to operate on entities generically — building queries, extracting keys, computing diffs.
Positive Impact
  • Automatic key extraction — primary keys extracted without type knowledge
  • Automatic table views — UI generates columns and forms from metadata
  • Deep cloning — notification diffing without type-specific code
  • Schema-driven behavior — adding a type with decorators gives full CRUD support
AI Acceleration
AI registers decorators with a single call: AddPrimaryKeyDecorator(&Type{}, "Field"). The introspector handles key extraction, index building, and query optimization automatically. No custom metadata code ever needed.
Relevant Rules
introspector-nodes-params.md prime-object-references.md js-protobuf-field-names.md

Query Language
IQuery, IExpression, ICondition, IComparator • API.go
Purpose
A structured query model with filtering, sorting, pagination, aggregation (COUNT, SUM, AVG, MIN, MAX), GROUP BY, and HAVING. Expressed as L8Query strings and used uniformly by the UI, API, ORM, and cache. One query language everywhere — no impedance mismatch.
Positive Impact
  • One query language everywhere — same syntax in JS, HTTP, ORM, and cache
  • Automatic filtering — Match(obj) tests any object against criteria
  • Built-in pagination — consistent across storage backends
  • Map-reduce support — distributed queries natively
  • Aggregate support — dashboard KPIs without custom code
AI Acceleration
AI constructs L8Query strings with a simple grammar: select [cols] from [Type] where [cond] limit [n] page [p] sort-by [field]. No query builder API, no ORM DSL — just a string. Same syntax for UI, tests, and mocks.
Relevant Rules
l8query-rules.md protobuf-model-names.md setup-configuration.md layer8d-data-source.md
Example
select * from Employee where lastName=Smith limit 10 page 0 sort-by lastName select * from SalesTerritory where isActive=true limit 15 page 2 sort-by name descending

Data Elements
IElements • API.go
Purpose
The universal data container. Every service method accepts and returns IElements. Carries typed data objects, their keys, errors, query metadata, and serialization support. Eliminates the need for service-specific response types.
Positive Impact
  • Uniform response type — router, cache, serializer, web bridge all use IElements
  • Error propagation — errors are part of the container, not exceptions
  • Notification support — same container carries CRUD results and real-time updates
  • Metadata attachment — pagination metadata travels with the response
AI Acceleration
AI never writes response types. Every service returns IElements, so AI uses one pattern everywhere: call method, check Error(), iterate Elements(). 3 lines for every service interaction.
Relevant Rules
layer8d-table-pagination-metadata.md report-infra-bugs.md

Web Service Bridge
IWebService, IWebServer, IWebProxy • Web.go
Purpose
Bridges Layer 8 internal services to HTTP/REST. Maps HTTP methods to Layer 8 actions, handles protobuf-to-JSON conversion. Any service with a WebService configuration is automatically exposed as REST endpoints with zero HTTP handler code.
Positive Impact
  • Zero HTTP code — no handlers, no request parsing, no response formatting
  • Automatic endpoints — new service = new REST API, no HTTP work
  • Plugin extensibility — custom web extensions without modifying core
  • Single web server — all portals and services from one process
AI Acceleration
AI never writes HTTP handlers or middleware. URL pattern is always /{apiPrefix}/{serviceArea}/{ServiceName}. AI constructs correct API calls without consulting documentation — the pattern is deterministic.
Relevant Rules

Serialization
ISerializer • Serializer.go
Purpose
Pluggable serialization supporting three modes: Binary (protobuf), JSON, and String. The framework selects the appropriate serializer based on context — binary for network, JSON for HTTP, string for logging. Service code never deals with serialization.
Positive Impact
  • Format independence — services work with typed structs, never raw bytes
  • Per-type optimization — custom serializers without pipeline changes
  • Resource-aware — serializers access registry, security, introspector
AI Acceleration
AI never writes serialization code. Types are protobuf messages with automatic binary and JSON support. New types get serialization for free — no marshaling, no field mapping, no format negotiation.
Relevant Rules

Distributed Cache
IDistributedCache, IServiceHandlerCache • Services.go
Purpose
In-memory cache with CRUD operations that automatically generate property change notifications. Every data change produces a notification set describing what changed (old/new values, which fields). Combined with IReplicationCache for multi-node data distribution.
Positive Impact
  • Automatic change notifications — real-time UI updates with zero application code
  • Query-capable cache — pagination and IQuery filtering in-memory
  • Metadata aggregation — counts/totals computed incrementally
  • Single-owner consistency — cache is authoritative, no invalidation needed
AI Acceleration
AI never writes cache management code. The ORM provides caching and notifications through SLA configuration. AI generates UI code that subscribes to WebSocket notifications — no custom synchronization needed.
Relevant Rules
single-owner-database-table.md layer8d-table-pagination-metadata.md

Event System
IEvents • Events.go
Purpose
Typed event posting API supporting 17 event categories: Audit, System, Monitoring, Security, Integration, Network, Kubernetes, Performance, Syslog, Trap, Compute, Storage, Power, GPU, Topology, Automation, and generic. Events flow through the VNic to the events service.
Positive Impact
  • Uniform observability — all events flow through one channel
  • Typed categories — dedicated method per category ensures correct fields
  • Integrated with IResources — available via resources.Events()
  • Decoupled producers/consumers — fire-and-forget posting
AI Acceleration
AI selects the appropriate typed method (e.g., PostAuditEvent, PostSecurityEvent) and populates the struct. The typed API prevents wrong field structures — the compiler catches mismatches.

Persistent Storage
IStorage • Serializer.go
Purpose
Key-value storage interface for persistent backends. Provides Put, Get, Delete, and Collect (filter-based retrieval). The ORM uses IStorage to persist data — whether the backend is PostgreSQL, SQLite, or filesystem, the service code is identical.
Positive Impact
  • Backend agnosticism — swap databases without changing service code
  • Filter-based collection — server-side filtering without full data loads
  • Cache coordination — CacheEnabled() optimizes query paths
AI Acceleration
AI never writes database queries. The ORM translates IQuery to SQL behind IStorage. AI declares storage needs through the SLA and never interacts with the database directly.
Relevant Rules
never-touch-vendor-or-git.md vendor-third-party-code.md

Structured Logging
ILogger • Logger.go
Purpose
Five log levels (Trace, Debug, Info, Warning, Error) with a simple API. Accessible via resources.Logger() and used consistently throughout the system. Combined with l8logfusion for distributed log collection across all nodes.
Positive Impact
  • Consistent log levels — uniform format system-wide
  • Centralized control — SetLogLevel changes verbosity with no restarts
  • Distributed collection — logs from all nodes aggregated in System UI
AI Acceleration
AI uses resources.Logger().Info(...) for all logging. No framework choice, no format decisions, no configuration. The pattern is always the same.

Message Envelope
Message • Message.go, MessageMarshal.go, MessageUnmarshal.go
Purpose
The universal wire format for all network communication. Carries routing info (source, destination, service), delivery metadata (priority, multicast mode, action), authentication context (AAA ID), and optional transaction state. Body is always encrypted; header is plaintext for routing.
Positive Impact
  • Security by default — no unencrypted messaging path exists
  • Priority-based QoS — eight priority levels (P1-P8)
  • Transaction observability — full lifecycle timestamps in every message
  • Efficient cloning — Clone, CloneReply, CloneFail for routing variants
AI Acceleration
AI never constructs Message objects directly — IVNic handles message creation internally. The Message struct is infrastructure that AI benefits from without needing to understand its internals. This is intentional design.
Relevant Rules
framework-interface-boundaries.md never-edit-vendor.md

Transaction Management
ITransactionConfig • Services.go
Purpose
Declares whether a service participates in distributed transactions, how replication works, and how transaction keys are extracted. The framework uses this configuration to implement two-phase commit, replication, and lifecycle management.
Positive Impact
  • Declarative transactions — SetTransactional(true) enables 2PC automatically
  • Configurable replication — ReplicationCount() declares replica count
  • Voter participation — read-only replicas opt out of voting for performance
AI Acceleration
AI enables transactions by setting a single flag on the SLA. No transaction manager code, no lock management, no rollback handlers — the framework provides it all.

Map-Reduce
IMapReduceService • Services.go
Purpose
Defines how results from distributed queries are merged. When a query fans out to multiple service areas (e.g., inventory across warehouses), each area returns results, and the Merge function combines them into a single response.
Positive Impact
  • No client-side merging — framework handles fan-out and merge transparently
  • Custom merge logic — per-service semantics (sum, concat, dedup)
  • Single query API — client sends one query, gets merged results
AI Acceleration
AI enables map-reduce by setting mapreduce true in L8Query strings. The framework handles distribution and merging. AI never writes fan-out, collection, or merge code.

The Economic Optimization
⚙

Configuration Over Implementation

Services are declared, not implemented. The SLA declares what a service needs; the framework provides it. Callbacks declare validation rules; the framework enforces them. Security rules are declared in JSON; the framework applies them. The ratio of configuration to implementation approaches 100:1.

✓

One Way to Do Each Thing

One way to communicate (IVNic), store data (IStorage), query (IQuery), secure (ISecurityProvider), log (ILogger), send events (IEvents). This eliminates the "which approach?" decision that consumes developer time and creates inconsistency.

■

Interface Boundaries as Firewalls

Every interface in ifs/ prevents coupling. A service cannot depend on another service's implementation — only on IVNic. The ORM cannot depend on a specific database — only on IStorage. Any component can be replaced, upgraded, or scaled without affecting others.

For AI, these three principles transform software development from creative problem-solving into deterministic template application.
AI does not need to design — it applies patterns. AI does not need to decide — the framework decides.
AI does not need to debug integration issues — the interfaces prevent them.
